# A-Roll 稿件生产指南（选题素材 → 可对照录制的视频稿件）

阶段 A 的完整规范。产出的稿件要让用户**拿着就能开录**：口播文案逐句可念、拍摄提示明确、B-Roll 已在写稿阶段预绑定特效库模式 id——录完直接进阶段 B 制作特效。

## 输入与产出

- **输入**：选题（一句话）+ 背景材料（文档/逐字稿草稿/产品/链接/素材文件夹/memory）
- **产出（按需选一）**：
  - **逐字稿**（轻量，适合 1~3 分钟口播+演示类）：段落化口播文案 + 【拍摄提示】
  - **分镜稿 STORYBOARD**（完整，适合产品发布/商业化视频）：分镜表 + 质量门禁自检 + 评审摘要

两种产物都必须包含**预排 B-Roll 列**（绑定库内模式 id），这是稿件与特效库无缝衔接的关键。

## 第一步：选题立意（Message 先行）

写任何一句台词前，先定三件事：

1. **Message**：一句话核心主张（如「一个人点一个按钮，3 分钟搭起 AI 员工团队」）。全片每一镜都要服务它，删掉不服务的内容
2. **叙事弧**：从下面选型——
   - `Problem→Solution + Reveal`：痛点铺垫 → 「所以我们做了 X」揭示 → 演示 → CTA（产品发布首选）
   - `反差钩子 → 解法 → 算账/实证 → 总结`：都说贵 → 我找到省钱法 → 算账 → 行动（测评/技巧类首选）
   - `成品先行 → 怎么做到 → 教程 → CTA`：先看结果再拆解（教程类首选）
3. **节奏声明**：每段的速度感（钩子快推 → 痛点慢 → 揭示定场 → 演示中速 → CTA 定场），写在稿件头部

## 第二步：口播写作规范

- **短句分行**：一行一口气，每行 ≤ 20 字；逗号处换行，让用户照着念不憋气
- **口语化**：「我们来算一笔账」而不是「以下进行成本核算」；疑问句和停顿制造对话感
- **时长估算**：中文口播 ≈ 4.5 字/秒；每段标注预计时间区间（如 `0:20 - 0:50`）
- **【】提示不念出**：拍摄/剪辑/演示动作提示放【】内（如【屏幕演示：点击模型下拉，选中要演示的模型】）
- **钩子三秒定律**：第一句必须是反差断言/成品展示/利益承诺，禁止自我介绍开头
- **痛点共鸣段（钩子后 5~30s 必做）**：见下节「痛点共鸣方法论」——给解法之前先让观众点头「对对对，我就是这样的」
- **金句收口**：每个段落用一句可独立传播的话收尾（「AI 员工还没上岗，你先当了一晚上运维」）
- **CTA 单一**：主行动指令只留一个（下载/关注二选一），互动问题降级为收尾彩蛋

### 痛点共鸣方法论（钩子后 5~30s，先点头再给解法）

钩子只负责「停下来」，痛点共鸣段负责「留下来」：在抛出任何解法/产品/教程之前，先用观众自己的日常把他钉在屏幕前，让他心里冒出「对对对，我就是这样的」。没有这一段，后面的解法再好观众也觉得「与我无关」。

写法四件套（按强度递进，选 2~3 个组合，总时长 5~25s）：

1. **第二人称场景复现**：用「你」+ 具体动作/工具/时刻还原观众的真实日常，精确到按钮和报错——「你是不是也这样：网页里问完 AI，复制出来，粘到编辑器，跑一下，报错，再粘回去问」。判断标准：观众听完能脑补出自己昨天的画面
2. **说出他没说出口的细节**：写他经历过但从没对人讲过的小狼狈（越私密越有效）——「每个月 ¥xxx 会员费，扣款短信来的那一秒你都会犹豫一下要不要退」。这是共鸣强度最高的一招
3. **连发递进确认**：2~3 连问/连排，节奏从轻到重，逼观众连续点头——「教程收藏了 38 个，一个没跑通；模型换了 4 个，效果还是那样；最后你开始怀疑是自己的问题」。注意最后一条要落在情绪而不是事实
4. **代价数字化**：把痛点折成他真实付出的钱/时间/次数——「一次 2 块，一天 30 次，一个月就是一台 iPhone」。与算账类叙事弧天然衔接

铁律：

- **痛点必须具体到可验证**：「效率低」「很麻烦」是空话；「跑一半报错、重来又是 20 分钟」才是痛点。空泛痛点 = 没有痛点
- **痛点要选目标观众的，不是自己的**：写之前先回答「这条视频拍给谁」，痛点从他的日常取材；自己的痛点只有在与观众重叠时才能用
- **只共鸣不嘲讽**：站在观众一边骂工具/骂厂商/骂流程，永远不要让观众觉得被说「你不行」
- **点头之后立刻转折**：共鸣段结尾必须接「直到我发现…/其实问题不在你…」类转折句，把情绪势能引向解法；停留超过 30s 会从共鸣变成贩卖焦虑
- B-Roll 配合：痛点共鸣段优先绑 `terminal-error-hell` / `message-feed-stack` / `persona-card-trio` / `hud-cross-points` / `quote-card`（见 narrative-index「痛点 / 问题呈现」组），画面演他的日常，比口播单独说强一倍

## 第三步：A/B-Roll 配比规划（写稿时同步做）

逐句标注 A-ROLL（出镜口播）或 B-ROLL（画面叠加/屏录/AI 图），B-ROLL 句子**当场翻 `assets/style_library/narrative-index.md` 绑定模式 id**：

| 镜号 | 台词 | 类别 | 画面描述 | 素材策略 | B-Roll 模式 | 预估时长 | 本镜目的 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 我桌面上跑着一支 AI 员工团队 | A-ROLL | 人物居中+关键词字幕 | - | `typewriter-keyword-card` | 4s | 反差断言停住观众 |
| 2 | 有人盯消息有人整资料 | B-ROLL | Agent 卡片墙横移 | 屏录 | `agent-team-grid` | 7s | 给钩子上证据 |

列说明：

- **素材策略**：屏录（写明录制指令：页面/操作/停留秒数/「真实输出不摆拍」）/ AI 图（写图像提示词，风格跟项目 STYLE 文件）/ 排版动画（纯特效库实现）
- **B-Roll 模式**：库内 id；A-ROLL 句若需要字幕强调也可以绑（如 `caption-karaoke`）；确无匹配标 `NEW: 设想`
- **本镜目的**：一句话说清这镜为什么存在，说不清就删镜

## 第四步：质量门禁（分镜稿必做自检，逐字稿抽查）

| 门禁 | 阈值 |
| --- | --- |
| B-Roll 覆盖率 | ≥ 40%（口播全程怼脸是大忌） |
| 最长 A-Roll 连续段 | ≤ 20s |
| 最长 B-Roll 连续段 | ≤ 30s（太久不见人会掉信任感） |
| Pattern Interrupt 间隔 | ≤ 60~90s 一次强刺激（logo impact / 爽点 / 转场 / SFX） |
| 钩子 | 前 5s 有反差断言或成品展示 |
| 痛点共鸣段 | 钩子后 30s 内有 ≥1 处「观众会点头」的具体痛点复现（第二人称场景/没说出口的细节/代价数字化），且结尾带转折句 |
| CTA | 主动作唯一 + 画面事件（字卡/角标）+ 结束留 2.5s |
| 每镜目的 | 全部非空 |
| 证据类镜头 | 演示/报错/数据一律真屏录不摆拍 |

## 第五步：交付与衔接

1. 稿件存到视频项目目录（命名：`<标题>-逐字稿.md` 或 `STORYBOARD.md`），分镜稿头部带 Message/叙事弧/节奏声明/预估总时长
2. 给用户的同时附**评审摘要**（每段 30 秒版一行概括），方便快速过稿
3. 用户录制完成后进入阶段 B：分镜表的「B-Roll 模式」列直接就是节拍表的「特效模式」列——把台词时间戳换成成片时间戳即可开工
4. 多版本迭代在稿件头部记 v2/v2.1 变更日志，不要静默覆盖

## 风格资产复用

- 项目若有 `BROLL-STYLE.md`（视觉语言规范），所有 B-Roll 画面描述/提示词必须遵循它
- 没有就在首次产出分镜稿时一并生成一份（配色/元素/屏录包装/字幕规范），后续全项目复用
