# 已有视频自动模式

触发示例：`<视频路径> 全自动剪辑`、`<视频路径> 这个视频，走自动模式`。明确要求“只剪辑”“不做封面”等时缩小执行范围。

本模式是 Agent 按顺序编排各阶段的执行流程，没有后台进程。剪辑、清洗、字幕、特效和风险自检由本 Skill 自带；封面图片、标题正文标签和发布工作台依赖宿主环境里的对应能力，可选搭配公开仓库 [video-publish-workbench](https://github.com/mileson/video-publish-workbench)。缺少某项能力时，先完成可独立执行的阶段，在交付说明里写明缺口，不自动安装替代插件。

## 默认与覆盖

- 范围：剪辑与字幕，标题、正文与逐平台标签，封面图片，汇总发布材料。只有收到明确的发布指令才对外发布，已有明确授权不重复索取。
- 自动选择：AI 选定标题、正文、标签组合和封面成品，保留可编辑的候选与选择理由，不把挑选变成用户的前置任务。用户明确锁定的内容优先；AI 的选择记为 `source: ai`，封面审批记为 `ai_checked`，不写成用户已确认。
- 默认目录：复用项目根目录。根目录交付 `【成片】<主题名>.mp4` 与 `【逐字稿】<主题名>.srt`，过程统一放在 `视频剪辑明细/`，最终封面放根目录 `封面图/`，发布文案为根目录 `【发布文案】<主题名>.md`。使用发布工作台时，工作台为根目录 `<主题名>-视频预发布工作台.html`，发布数据与回执放在明细 `publish/v00N/`。用户指定目录时优先遵从。
- 默认比例：3:4 主版，4:3 与 16:9 衍生版。明确只要一种比例时只交付该比例。
- 默认平台：小红书、抖音、快手、视频号、B站、YouTube。这只表示文案按这些平台准备，不等于已授权发布。
- 标签来源：优先用户提供的来源；其次平台公开的话题或活动页，核对起止日期与参与条件；没有可核验来源时使用有内容依据的通用标签。记录来源链接、获取时间与入选理由，不把话题热度写成流量保证。
- 优先级：本次用户指令 > 已确认的项目决策 > 本机 `data/auto-mode.local.json` > 本文默认。该文件可设置 `cover_ratios`、`platforms`、`tag_sources`、`paid_research_budget`，字段样例见 `data/auto-mode.example.json`；未设置的字段不猜测授权。
- 账号、凭证、私人模板和 `*.local.json` 不进入仓库（`.gitignore` 已排除）。引用的外部 Skill 或工具要在交付说明里列出，不把它们称为已打包的能力。

## 执行与续做

标签调研保存原始候选、抓取时间、日期与条件核验及最终选择理由到明细 `tag-research/`。一次获取后在本地按平台筛选；平台容量、空结果和失败按所用工具的说明处理，不重复请求，不把关键词命中当作活动奖励资格。

封面按需读取已有的版式案例。先理解授权的人像素材，再把身份与风格共性分开输入；人物重新生成，姿势表情服务当前主题。局部返修只使受影响的封面及下游资产校验失效；标签变更只更新文案相关数据，不重生封面。

交接封面时传递绝对路径、实际尺寸与比例、文件大小、SHA-256、主版与衍生版关系，以及 `ai_checked` 或 `user_approved` 的真实状态。封面角色与平台的对应关系以所用发布工作台的合同为准。更换图片时同步当前选择和待执行任务，保留页面草稿与历史回执，不能只覆盖同名 PNG 却沿用旧的 size 与 sha256。

在既有项目 `视频剪辑明细/` 维护 `auto-package-state.json`：记录 `project_root`、`process_root`、主题名和根目录 `final_video_path`、`final_transcript_path`、`final_cover_dir`、`workbench_path`、`publish_copy_path`，保存输入视频指纹、已确认约束及来源、所用模板、产物绝对路径、阶段状态与待解决问题。每项偏好来源用 `user`、`profile`、`template` 或 `ai`，不能把 AI 决策记成用户回复。

阶段状态使用 `pending / running / completed / blocked / stale`。输出存在不等于完成，必须附检查结果；复用时检查输入指纹、约束和产物。变更只使受影响阶段失效：改封面不重剪视频，改标签不重生封面；改标题时检查已生成封面文字与主题，只有受影响图片需要更新。恢复执行复用现有文件和进程。

1. **读取与剪辑**：复用字幕和剪辑决策，没有则转写。已有录制视频从阶段 6 进入，不补跑选题、口播稿和数字人阶段。自动决定常规节奏和字幕样式，保持口播事实；语义不确定的片段先保留并记录原因，不为“精剪”盲删。屏录教程按实际证据需求决定是否增加 B-Roll，不为覆盖率制造无关镜头。完成字幕、剪口、屏录敏感信息及音画检查。按入口的逐字稿规则生成完整成片 SRT，优先复用已校正的最终字幕，缺失时用现有本地转写工具；校验后交付到成片同级。
2. **标题、正文与标签**：使用本片最终逐字稿和实际画面作为事实依据。环境里有发布工作台 Skill 时，读取它的入口并沿用其候选数量、标题限制与标签容量规则；没有时由 AI 自行拟定。AI 选定一个公共标题、一个正文版本及各平台标签，派生逐平台标题（含视频号短标题），保存选择数据并记录选择来源。此时封面角色可暂空，不把中间数据当作完整套餐交付。无需等待用户挑选，接着执行封面步骤。
3. **封面图片**：把实际项目根目录、明细目录、视频主题、选定标题、内容摘要、比例和已有素材显式传给封面能力。宿主环境有生图能力时实际生成并逐张目检，不能只交付提示词、模板路径或占位图；没有生图能力时交付封面文案与提示词，状态记为 `blocked`。封面可按版面压缩标题，但不改变主题和承诺。候选和返修先进入明细 `work/封面制作/`；主版通过 AI 质检后再生成其他比例，每个比例检查文字、构图、真实尺寸与风险。选定图片按主题与比例命名交付到根目录 `封面图/`，标记 `ai_checked`。主版需要返修时先修主版，避免同时产生三套不同方向。
4. **汇总发布材料**：生成根目录 `【发布文案】<主题名>.md`，汇总已选的公共标题、正文及逐平台标题和标签，标明 AI 自动选定、未经用户确认。使用发布工作台时，复用第 2 步的调研、候选和选择，补齐封面路径与角色，工作台输入、当前选择与 Markdown 三处保持一致，完成文件校验与页面实看。用户后续的修改同步更新这些位置，保留用户最新选择、制作记录与必要的历史证据。

收尾核对：根目录成片和逐字稿与各自版本包副本指纹相同，逐字稿格式与成片时间轴有效，根目录最终封面与发布文案存在且文案与当前选择一致，全部当前交接路径存在，过程产物均位于明细目录。已有项目整理时保留选择和历史回执，记录新旧路径映射，不触发重复发布。

每阶段独立落盘检查证据。媒体编码、图片生成和平台操作串行执行，不为自动模式启动重复实例。终点交付根目录成片 MP4 与同名 SRT 逐字稿、明细内 SRT/ASS、各比例封面图片、包含标题正文及逐平台标签的发布文案、有工作台时的默认选择，以及未验证事项。所需图片未实际生成、文案或标签未填充、工作台仍为空槽时，不得把完整套餐标记为 completed，记录具体缺口并交付已完成部分。自动模式保留质量检查，省去重复的偏好问答。

## 需要用户输入的情况

只有影响执行且无法从现有信息解决的缺口才提问，例如缺少源视频、要求使用真人身份但没有授权素材、必须使用的付费来源超出已授权预算。普通视觉选择由 AI 处理。缺少可复用人物时可选合适的无人模板；用户明确要求特定人物时，不得悄悄替换身份。

付费调研没有预算授权时继续免费部分并记录覆盖缺口，“全部自动”不等于无限费用。只准备工作台时，不因缺少发布浏览器上下文而提问。实际进入已授权的填入或发布步骤时，沿用已确认的浏览器上下文，未配置时询问一次并保存项目选择。使用发布工具的队列和回执规则：忙碌则暂停队列，结果不明先查现有任务，不重复上传。用户接管后停止并发的页面操作，按可观察状态或用户确认归档。

## 自动风险审查衔接

自动模式依次执行三个检查点：视频审查 R01/R02/R04，封面审查 R03，发布文案审查 R05/R06/R07。规则和报告格式都在本 Skill 的 `references/distribution-risk-knowledge.md` 与 `references/distribution-risk-review.md`，复用各阶段的检查产物，不要求用户确认检查开始或无命中通过。把三个报告的引用、检查范围、输入与规则版本、目标平台和未处理风险记入 `auto-package-state.json` 的阶段记录；没有实际验证时不得标 completed。

无风险时静默进入下一阶段，发现风险才主动给出具体表格与改法。影响已确认内容或发布决策时，只暂停相关动作，其余独立阶段继续；用户对同一风险的明确选择可以复用。改标签只使文案检查失效，改封面复查对应比例与文案一致性，改口播或时间轴复查音频、字幕和相关画面，不启动无关的重剪或重生成。自动模式不自动隐藏、删除或重发线上作品。
